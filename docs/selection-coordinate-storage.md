# Canonical linked-selection coordinate rows

`BattleSelectionWork` owns one 0x30-byte allocation. Both constructors populate four interleaved signed X/Y pairs at +0x0C, with an eight-byte row stride; the backdrop fade remains at +0x2C. Movement and threshold consumers independently establish the two component meanings. No interface requires a named-field row type. Represent only this member as actual `s32 positions[4][2]`, and migrate all its producers and consumers consistently. The shared `BattleSelectionPosition` type used by other objects is unchanged.

This is the allocation's canonical storage, not a second cast view over another type. All migrated accesses use the complete owner. The earlier `SelView` is not evidence for the choice: its history derives from a matching draft of the renderer itself. The constructor and other consumers support the array-of-pairs representation without identifying the unique original C syntax.

The initializer preserves the native row-write phase while keeping C pointer arithmetic within real array objects. Its existing countdown `i = 3..0` selects forward row `3 - i`; each iteration acquires `destination = &allocated->positions[3 - i][1]`. `destination[-1]` is that row's X and `destination[0]` is its Y. Both accesses remain within the same actual two-element subarray. The scalar pointer is never advanced into the next row. A scalar cursor derived from a named Y field and stepped through neighboring fields or rows does not gain valid array bounds merely from contiguous byte offsets.

The complete Y-address expression is `allocation + 0x10 + 8 * (3 - i)`. It exposes the native induction directly: initialize a Y-address cursor at +0x10, store X at -4 and Y at 0, then advance eight bytes per row. The rejected row-base formulation instead carried +0x0C and reconstructed +4 inside every iteration. No fabricated alias class, overlapping record, cast, qualifier, dummy dependency, or register constraint is needed. The byte-qualified EE GCC capture locates the transformation in `rtl.09.loop`: it recognizes countdown pseudo87 (initial 3, step -1), combines the X/Y address uses (UID74/79) with the Y-address expression (UID63), and creates pseudo101. UID142 initializes it to allocation+16; UID139 advances it by8; the stores become `[101-4]` and `[101]`. The preceding `rtl.08.gcse` still evaluates `(3-i)<<3` and adds allocation+16. Final delay-slot output carries the cursor in `$4` and places its increment in the loop-branch delay slot. This is compiler-derived pointer induction from bounded row indexing, not cross-subarray pointer arithmetic written in C.
